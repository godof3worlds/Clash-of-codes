# Final Technical Stack & Complete Functional Architecture

## 1. Project Overview

The project is an **AI-powered, adaptive, gamified coding-learning platform with real-time multiplayer coding competitions**.

The platform combines:

* AI-generated coding problems
* Adaptive difficulty
* Online code execution
* AI-powered code analysis
* Personalized AI mentoring
* AI-generated learning courses
* Web-assisted documentation
* Gamified progression
* 2D interactive island maps
* Real-time multiplayer Clash rooms
* Territory/pathway capture
* Leaderboards
* Badges
* Streaks
* XP
* Learning analytics

The core learning loop is:

```text
LEARN
  ↓
PRACTICE
  ↓
CLASH
  ↓
CODE
  ↓
EXECUTE
  ↓
SOLVE
  ↓
CAPTURE TERRITORY
  ↓
AI FEEDBACK
  ↓
ADAPT DIFFICULTY
  ↓
IMPROVE
```

The central design principle is:

> **Gamification creates engagement, multiplayer creates competition, and AI creates personalization — but learning remains the primary objective.**

# 17. Important Multiplayer Rule — Server Authority

The browser must **not be trusted to determine important game outcomes**.

For example, the client must not simply send:

```text
"I captured Territory C."
```

and have the server believe it.

Instead:

```text
Player submits code
       ↓
Backend
       ↓
JDoodle execution
       ↓
Test validation
       ↓
Backend determines success
       ↓
Backend validates territory access
       ↓
Database updated
       ↓
Realtime event emitted
       ↓
All players see updated territory
```

The backend/database is authoritative.

This prevents basic cheating.

---

# 18. Territory Capture Rules

A player can only capture a territory if:

1. The player is allowed to participate in the match.
2. The territory is currently available.
3. The territory is connected to an area the player controls or can legally access.
4. The player receives the corresponding challenge.
5. The submitted code passes the required tests.
6. The backend validates the attempt.
7. The match is still active.

Only then is the territory captured.

---

# 19. Race Conditions

Multiple players may attempt the same territory simultaneously.

Example:

```text
Player A ──► Territory X
Player B ──► Territory X
```

Both might solve the problem at nearly the same time.

The backend must use an atomic transaction/locking strategy.

Only one valid capture should be accepted according to the game's defined rules.

Possible result:

```text
Player A succeeds first
       ↓
Territory X = BLUE
       ↓
Player B receives:
"Territory already captured."
```

This must be handled server-side rather than relying on frontend timing.

# 26. Handling Disconnects

Players can disconnect.

The room should distinguish:

```text
CONNECTED
DISCONNECTED
RECONNECTING
ELIMINATED
FINISHED
```

If a player temporarily disconnects:

* Their territory remains theirs.
* Their progress remains.
* They can reconnect to the room if the match is still active.
* The server determines whether they are considered active.

The frontend should display:

> "Reconnecting..."

rather than immediately declaring the player defeated.

---

# 27. Player Leaving

If a player intentionally leaves:

* They are removed from active participants.
* Their captured territories follow the defined match rule.
* The remaining players are notified.

For the initial implementation, captured territory can remain captured rather than automatically reverting.

---

# 28. Clash End Conditions

A match can end when:

### Option A — Goal Reached

First player to reach the final territory wins.

### Option B — Time Limit

Match ends after a fixed duration.

### Option C — Full Map

Match ends when all relevant territories are captured.

### Recommended

Use:

> **First player to reach the final objective OR the time limit expires.**

If the timer expires, rank players based on:

1. Territories captured
2. Difficulty-weighted points
3. Completed challenges
4. Tie-breaker based on validated completion timestamp

---

# 29. Clash Score

The multiplayer score should not simply be:

```text
number of territories
```

A difficult territory should be worth more than an easy territory.

Conceptually:

```text
Territory Points =
Base Points × Difficulty Weight
```

Then:

```text
Match Score =
Territory Points
+ Completion Bonuses
+ Objective Bonuses
```

Do not make speed the only factor.

A player who solves a difficult challenge correctly should receive meaningful credit.

---

# 30. Multiplayer Anti-Cheat Principles

The client should never directly control:

* Score
* Territory ownership
* Completion status
* Match winner
* Difficulty result
* XP rewards

The backend verifies these.

For example:

```text
Client:
"I solved it."

Backend:
"Show me the execution result."

JDoodle:
"Tests passed."

Backend:
"Territory capture accepted."

Database:
"Territory belongs to Player A."

Realtime:
"Broadcast territory update."
```

The platform explicitly separates AI responsibilities from deterministic systems.

### AI decides/suggests:

* Problem wording
* Explanations
* Recommendations
* Learning material
* Feedback

### Backend determines:

* Authentication
* Authorization
* Score
* Territory ownership
* Match state
* Difficulty state
* Rewards

### JDoodle determines:

* Whether submitted code executes
* Compilation errors
* Test execution results

### Supabase determines:

* Persistent application data

This separation greatly improves reliability.

# 37. Adaptive Difficulty Engine

Difficulty ranges from:

```text
1 → 10
```

The engine considers:

* Correctness
* Recent success rate
* Attempts
* Hints
* Time
* Compiler errors
* Topic mastery
* Existing difficulty

Conceptually:

```text
Performance Signal =
    Correctness
  + Recent Success
  + Topic Mastery
  + Appropriate Speed
  - Excessive Hint Usage
  - Repeated Failure
```

Difficulty changes gradually.

```text
Excellent performance
       ↓
Difficulty + small step

Stable performance
       ↓
Difficulty unchanged

Repeated struggle
       ↓
Difficulty - small step
```

No single failed attempt should suddenly make the learner's problems extremely easy.

---

# 38. Difficulty and Multiplayer

For competitive Clash rooms, completely independent difficulty can create unfair matches.

Therefore, the matchmaker should attempt to group players within a reasonable skill range.

Example:

```text
Player A: Difficulty 5
Player B: Difficulty 5
Player C: Difficulty 6
Player D: Difficulty 5
```

This creates a reasonably competitive match.

A player's long-term difficulty model remains independent from the match itself.

# 55. Realtime vs Database

Realtime should not replace the database.

### Database

Persistent truth.

### Realtime

Fast synchronization.

```text
Database
   ↓
Persistent State

Realtime
   ↓
Live State Updates
```

If a client disconnects and reconnects, it should retrieve the current match state from the database and then resubscribe to Realtime.

# 84. Critical Architecture Rules

The implementation must follow these rules.

### Rule 1 — Server Authority

The client cannot decide:

* Winner
* Score
* Territory ownership
* Match state
* XP
* Rewards

### Rule 2 — AI Validation

AI-generated coding problems must be validated before being presented as official challenges.

### Rule 3 — Real Compiler Results

AI cannot claim that code passed or failed.

JDoodle/backend execution results are authoritative.

### Rule 4 — Secure Secrets

Private API keys remain server-side.

### Rule 5 — Database Truth

Supabase stores persistent match and learning state.

### Rule 6 — Realtime Synchronization

Supabase Realtime synchronizes live multiplayer changes.

### Rule 7 — Failure Is Learning

Failures should adjust difficulty and provide feedback rather than heavily punish the learner.

### Rule 8 — Fair Multiplayer

Players should be matched within a reasonable skill range.

### Rule 9 — Race Conditions

Simultaneous territory captures must be resolved atomically by the backend.

### Rule 10 — Reconnection

Temporary network failures should not immediately destroy a player's match.

### Rule 11 — Web Safety

Retrieved webpages are untrusted reference material.

### Rule 12 — Learning First

Gamification should encourage learning rather than manipulate attention.

# 87. Final Product Philosophy

The platform should feel like a **competitive 2D coding adventure**, not a conventional online judge.

A learner should be able to look at the screen and understand:

> "There is an island. There are multiple paths. Other players are competing against me. I need to solve coding challenges to capture territory and reach the objective."

But underneath the game is a serious adaptive learning engine.

```text
                    GAME
                     │
              makes learning
                engaging
                     │
                     ▼
                  CLASH
                     │
              creates competition
                     │
                     ▼
                  CODING
                     │
             demonstrates skill
                     │
                     ▼
                AI ANALYSIS
                     │
              explains mistakes
                     │
                     ▼
              LEARNER MODEL
                     │
             understands user
                     │
                     ▼
             ADAPTIVE ENGINE
                     │
            adjusts difficulty
                     │
                     ▼
                AI MENTOR
                     │
           recommends next step
                     │
                     ▼
                 PRACTICE
                     │
                     ▼
               NEXT CLASH
```

### The final concept is therefore:

> **A real-time multiplayer coding world where players compete across branching 2D island territories by solving programming challenges, while an AI learning engine continuously adapts the difficulty, analyzes their code, recommends what to study, and generates personalized learning paths.**

The **multiplayer game is the engagement layer.**

The **AI is the personalization layer.**

The **compiler is the execution authority.**

The **backend is the game authority.**

The **database is the persistent source of truth.**

And **education remains the purpose of the entire system.**
